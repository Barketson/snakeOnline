# Архитектура и контракты — онлайн-змейка с мультиплеером

Этот документ — источник истины для контрактов модулей. Реализатор (Kimi) кодит строго по нему,
ревьюер (архитектор) сверяет diff с ним. Требования к поведению описаны в README.md и PROTOCOL.md;
здесь зафиксированы только интерфейсы, форматы данных, ограничения и критерии приёмки.

## 1. Слои и поток данных

```
Браузер (public/*)  --WebSocket(JSON)-->  server/index.js --маршрутизация--> server/rooms.js
     ^                                        |                                 |
     |                                   статика /public                    server/game.js (чистая логика)
     +---------- state / lobby_update / countdown / round_end <---------------+
```

- **Авторитарный сервер**: вся логика (движение, столкновения, еда, очки) — только в `game.js`.
  Клиент шлёт только `input` (смену направления) и рисует пришедший `state`.
- **Чистый модуль `game.js`** не знает про сокеты/таймеры: принимает состояние и ввод, возвращает
  новое состояние и события. Это делает его тестируемым.
- Клиент никогда не считает исход столкновений; он интерполирует между двумя последними `state`.

## 2. Структура репозитория

```
/server   index.js (HTTP+WS, маршрутизация) · rooms.js (комнаты) · game.js (чистая логика) · config.js
/public   index.html · style.css · client.js (сеть, ввод, экраны) · render.js (canvas)
/test     game.test.js

SPEC.md · HANDOFF.md · PROTOCOL.md · README.md · ARCHITECTURE.md · Dockerfile · .dockerignore · package.json
```

## 3. Контракты модулей

### 3.1 `server/config.js` (все константы — здесь)

```js
export const TICK_RATE = 10;                 // тиков в секунду
export const TICK_MS = 1000 / TICK_RATE;
export const FIELD_SIZES = [ [40,30], [46,34], [52,38], [56,42], [60,44], [62,46], [64,48], [64,48] ]; // индекс = players-1
export const START_LENGTH = 3;
export const FOOD_POINTS = 10;
export const ROUND_DURATION_MS = 3 * 60 * 1000;
export const ROOM_CODE_ALPHABET = 'ABCDEFGHJKMNPQRSTUVWXYZ23456789'; // без 0/O/1/I/L
export const ROOM_CODE_LENGTH = 5;
export const MAX_PLAYERS = 8;
export const FOOD_PER_PLAYER = 2;            // еды = игроков + 2
export const INPUT_QUEUE_LEN = 2;
export const COUNTDOWN_SECONDS = 3;
export const EMPTY_ROOM_TTL_MS = 60 * 1000;
export const RECONNECT_WINDOW_MS = 15 * 1000;
export const RATE_LIMIT_PER_SEC = 30;
export const MAX_MESSAGE_BYTES = 1024;
export const NICK_MIN = 1, NICK_MAX = 16;
export const COLORS = [ /* 8 неоновых hex, уникальных */ ];
```

### 3.2 `server/game.js` — чистая логика (нет сети/таймеров)

```js
export function createGame(players, rng) // -> state
export function queueInput(state, playerId, dir) // dir = {x: -1|0|1, y: -1|0|1}, |x|+|y| === 1
export function step(state)                 // -> { state, events }
export function serialize(state)            // -> компактный объект для клиентов
```

- `players`: `[{ id, name, color }]` (порядок определяет спавн).
- `rng`: `() => number` в `[0,1)`, чтобы тесты были детерминированными.
- Внутреннее состояние (не то, что шлём клиенту):

```js
state = {
  grid: { w, h },
  tick: 0,
  status: 'countdown' | 'running' | 'ended',
  countdownTicks: COUNTDOWN_SECONDS * TICK_RATE, // 0 когда запущено
  snakes: [ { id, name, color, body: [{x,y}...], dir: {x,y}, alive: true,
              score: 0, pendingGrowth: 0, inputQueue: [] } ],
  food: [ {x,y}... ],
  roundEndsAtTick: number,
  rng,
}
```

- `queueInput`: добавить `dir` в `inputQueue` (до `INPUT_QUEUE_LEN=2`). Отклонять, если это текущее
  направление или 180° от последнего **эффективного** направления (текущее `dir`, а при непустой
  очереди — её хвост). Сообщение о развороте игнорируется бесшумно.
- `step` выполняет ровно один тик, **синхронно для всех змей одновременно**:
  1. Если `status === 'countdown'`: декремент `countdownTicks`; на нуле `status = 'running'`. Змейки стоят.
  2. Вычислить новые головы всех живых змей (применив один элемент из `inputQueue`, если есть).
  3. Применить `pendingGrowth`: если `> 0`, хвост не срезается и `pendingGrowth--` (хвост в этот тик **занят**);
     иначе хвост срезается и его клетка **свободна** для столкновений этого тика.
  4. Проверить столкновения по новым головам: стена, своё тело, чужое тело, лоб в лоб
     (две головы в одной клетке, либо обмен клетками за тик). Погибшие помечаются `alive=false`.
  5. Проверить еду (только для выживших): съел → `score += FOOD_POINTS`, `pendingGrowth += 1`, убрать яблоко.
  6. Тело погибших → еда: каждая **вторая** клетка тела (индексы 1,3,5…). Дозаполнить еду до `players + 2`.
  7. Проверить конец раунда: `≤ 1` выживший (в одиночной игре — `0`), либо `tick >= roundEndsAtTick`.
     При конце `status = 'ended'`.
  8. `events` — массив событий за тик: `{type:'eat', playerId}`, `{type:'death', playerId, reason}`,
     `{type:'roundEnd', winnerId|null}`.
- `serialize(state)` возвращает **только нужное для отрисовки** (см. §5, сообщение `state`).

### 3.3 `server/rooms.js` — комнаты и игровой цикл

Управляет комнатами, сокетами, тиком, рассылкой. Игровой цикл комнаты: отсчёт → `setInterval(TICK_MS)`
→ `step()` → рассылка `state` → по событию `roundEnd` рассылка `round_end`.

Функции (сигнатуры уточняет реализатор, но обязаны покрывать):
- создание комнаты (код по `config`, без похожих символов, без коллизий);
- вход по коду/ссылке (до 8 игроков; во время раунда — зритель);
- выход/разрыв: передача роли хоста следующему; в лобби — немедленный уход, в раунде — змейка едет прямо;
- общий счёт за сессию (сумма очков раундов) сохраняется в комнате;
- удаление пустой комнаты через `EMPTY_ROOM_TTL_MS`;
- `sessionToken` при входе — для переподключения (этап 5).

### 3.4 `server/index.js` — HTTP + WebSocket

- HTTP: раздача `/public` с правильными MIME, защита от path traversal (`../`), 404 для несуществующего.
- WebSocket (`ws`) на том же порту. JSON-парсинг в `try/catch`; битый JSON/неизвестный `type` → `error`,
  сервер не падает.
- Маршрутизация сообщений к `rooms.js`. Ошибка в обработчике одного сообщения/комнаты логируется
  и не роняет процесс и другие комнаты.

## 4. Ограничения (жёсткие, ревью проверяет их обязательно)

1. **Без фреймворков и сборщиков** на клиенте (чистые ES-модули, HTML, CSS, canvas). Сервер — `http` + `ws`
   (+ `node:test`). Никаких Express/React/Phaser.
2. **Без БД и регистрации**; всё состояние в памяти.
3. **Логика только на сервере.** В `public/*` не должно быть кода, определяющего смерть/очки/победителя.
4. **Пользовательский ввод никогда не вставляется в `innerHTML`.** Только `textContent` / экранирование.
5. **Все входящие данные валидируются**: тип сообщения, схема, размер ≤ `MAX_MESSAGE_BYTES`,
   ник 1–16 символов без управляющих, направление из `{[1,0],[-1,0],[0,1],[0,-1]}`, код комнаты по формату.
6. **Rate limit** ≤ `RATE_LIMIT_PER_SEC` сообщений с соединения; лишние игнорируются, грубое превышение — дисконнект.
7. **Один файл ≤ ~300 строк.** При превышении — вынести в отдельный модуль.
8. Никаких отладочных `console.log` в боевом коде (этап 6 чистит).
9. Порт — `process.env.PORT || 3000`; слушать `0.0.0.0`; клиент выбирает `wss://` при `https:` странице.

## 5. Протокол (контракт сообщений; полный текст — в PROTOCOL.md на этапе 2)

Все сообщения — JSON с полем `type`. Клиент→сервер: `create_room {name}`, `join_room {code, name}`,
`start_game`, `input {dir:[dx,dy]}`, `reconnect {sessionToken}` (этап 5).
Сервер→клиент: `room_joined {code, playerId, sessionToken, hostId, players[]}`,
`lobby_update {players[], hostId, code}`, `countdown {n}`, `state {...}`, `round_end {results[], sessionScore[]}`,
`error {code, message}`, `pong`.

### `state` (компактный, после каждого тика)

```js
{
  t: number,               // номер тика (для интерполяции и детекта рестарта)
  grid: { w, h },
  status: 'countdown'|'running'|'ended',
  countdown: number|null,  // секунд до старта (целое) во время отсчёта
  food: [[x,y], ...],
  snakes: [ { id, alive, body:[[x,y],...], dir:[dx,dy], score, len } ] // body[0]=голова, только живые+на отрисовку
}
```

## 6. Критерии приёмки

### Поэтапные
- **Этап 1**: `npm install --silent && npm test` зелёный; покрыты сценарии из `stage-1.md` (движение, запрет
  разворота, буфер 2 поворотов, рост, стена, своё/чужое тело, лоб в лоб в клетке и обменом, «хвост освобождает
  клетку», тело погибшего → еда, конец раунда: 1 выживший / 0 в соло / таймаут).
- **Этап 2**: `npm test` зелёный; `scripts/smoke.js` (2 WS-клиента: создать→войти→старт→повороты) получает
  `state` и в конце `round_end`; статика отдаётся.
- **Этап 3**: 4 экрана (меню/лобби/игра/итоги), ввод стрелки+WASD, `?room=CODE`, копирование ссылки,
  HUD и таблица итогов; пользовательский текст только через `textContent`.
- **Этап 4**: неон-стиль по §6, интерполяция между двумя `state`, частицы смерти, тряска при своей смерти,
  `devicePixelRatio`, без массового создания объектов на кадр, `shadowBlur` экономно.
- **Этап 5**: валидация/лимиты/переподключение работают; `scripts/abuse.js` (битый JSON, неизвестный type,
  огромное сообщение, флуд, разрыв+reconnect, уход хоста) не роняет сервер.
- **Этап 6**: `Dockerfile` + `.dockerignore`, `README.md`, wss за прокси, чистка логов, пройдены все пункты §7.

### Итоговые (§7 SPEC)
- [ ] `npm install && npm start` → `localhost:3000` без ошибок.
- [ ] `npm test` проходит.
- [ ] Две вкладки: создать комнату, войти по коду/ссылке, сыграть раунд.
- [ ] Столкновения по правилам, победитель определён верно.
- [ ] Плавно и играбельно при задержке ~100 мс.
- [ ] Закрытие вкладки одним игроком не ломает игру остальным.
- [ ] Некорректные сообщения не роняют сервер.
- [ ] Нет ошибок в консоли браузера и сервера.
