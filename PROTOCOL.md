# PROTOCOL — контракт сообщений (этапы 2, 5)

Все сообщения — JSON с полем `type`. Кодировка UTF-8. Сервер авторитативен:
клиент шлёт только намерения (`input`), сервер рассылает состояние (`state`).
Направление `dir` — массив `[dx, dy]`, где `|dx| + |dy| === 1`, значения в `{-1, 0, 1}`.

---

## Клиент → сервер

### `create_room` — создать комнату (создатель становится хостом)
```json
{ "type": "create_room", "name": "Алиса" }
```
- `name`: строка, 1..16 символов после trim, без управляющих символов.

### `join_room` — войти по коду
```json
{ "type": "join_room", "code": "K7Q2M", "name": "Боб" }
```
- `code`: ровно 5 символов из `ROOM_CODE_ALPHABET` (регистронезависимо на приёме).
- Если раунд идёт, вошедший получает `playerId`, но в текущем раунде — зритель
  (в `state` его змейки нет), участвует со следующего раунда.

### `start_game` — запустить раунд (только хост, из лобби)
```json
{ "type": "start_game" }
```
Ошибки: `not_in_room`, `not_host`, `already_running`.

### `input` — смена направления своей змейки
```json
{ "type": "input", "dir": [1, 0] }
```
- `dir ∈ {[1,0],[-1,0],[0,1],[0,-1]}`. Разворот 180° и повтор текущего
  направления игнорируются бесшумно (правила в `game.js`). Буфер — 2 направления.
- Вне раунда / для зрителя — игнорируется.

### `leave` — покинуть комнату
```json
{ "type": "leave" }
```
Немедленное удаление из комнаты в любом состоянии; хост передаётся следующему
игроку, в лобби рассылка `lobby_update`.

### `reconnect` — переподключение по токену сессии (этап 5)
```json
{ "type": "reconnect", "sessionToken": "3f6c…" }
```
- `sessionToken` выдаётся в `room_joined` при входе в комнату.
- Применение: клиент рвёт соединение во время раунда — сервер НЕ удаляет
  игрока, а держит его `RECONNECT_WINDOW_MS` (15 с) с `ws = null` (змейка
  едет прямо). Клиент за это время открывает новый WS и шлёт `reconnect`.
- Успех: сервер привязывает новый сокет к игроку (таймер окна снят) и шлёт
  ему лично `room_joined` с текущим составом (`hostId`/`players`) —
  ресинхронизация; дальше клиент получает обычные `state` и продолжает
  управлять своей змейкой.
- Ошибка `no_session`: токен не найден, окно истекло (игрок удалён) или
  игрок уже подключён живым сокетом. Ошибка не разрывает соединение.
- Разрыв в лобби (раунд не идёт) удаляет игрока сразу — `reconnect` после
  него вернёт `no_session`.

## Сервер → клиент

### `room_joined` — подтверждение входа/создания (лично вошедшему)
```json
{
  "type": "room_joined",
  "code": "K7Q2M",
  "playerId": "b3f…",
  "sessionToken": "3f6c…",
  "hostId": "a1b…",
  "players": [
    { "id": "a1b…", "name": "Алиса", "color": "#00FFFF", "isHost": true },
    { "id": "b3f…", "name": "Боб",   "color": "#FF00FF", "isHost": false }
  ]
}
```

### `lobby_update` — состав лобби (всем при входе/выходе/смене хоста/конце раунда)
```json
{
  "type": "lobby_update",
  "code": "K7Q2M",
  "hostId": "a1b…",
  "players": [
    { "id": "a1b…", "name": "Алиса", "color": "#00FFFF", "isHost": true },
    { "id": "b3f…", "name": "Боб",   "color": "#FF00FF", "isHost": false }
  ]
}
```

### `countdown` — целые секунды до старта 3, 2, 1 (всем, в начале раунда)
```json
{ "type": "countdown", "n": 3 }
```
Дублируется полем `countdown` внутри `state` во время отсчёта.

### `state` — состояние после каждого тика (всем, включая зрителей)
Тело — точный формат `serialize()` из `game.js` (HANDOFF.md):
```json
{
  "type": "state",
  "t": 42,
  "grid": { "w": 40, "h": 30 },
  "status": "running",
  "countdown": null,
  "food": [[12, 7], [30, 22]],
  "snakes": [
    {
      "id": "a1b…",
      "alive": true,
      "body": [[20, 15], [19, 15], [18, 15]],
      "dir": [1, 0],
      "score": 30,
      "len": 5
    }
  ]
}
```
- `t`: номер тика (интерполяция, детект рестарта).
- `status`: `countdown` | `running` | `ended`.
- `countdown`: целые секунды до старта или `null`.
- `msLeft`: миллисекунды до конца раунда (считается сервером из конфига)
  во время `status === 'running'`, иначе `null`. Позволяет клиенту показывать
  таймер раунда, не дублируя конфиг.
- `body[0]` — голова; у мёртвой змейки `alive:false` и `body:[]`, но `len` —
  финальная длина на момент смерти.
- Ключи змейки строго в порядке: `id, alive, body, dir, score, len`.

### `round_end` — итоги раунда (всем, после события `roundEnd`)
```json
{
  "type": "round_end",
  "results": [
    { "id": "a1b…", "name": "Алиса", "color": "#00FFFF", "score": 120, "len": 9,  "place": 1 },
    { "id": "b3f…", "name": "Боб",   "color": "#FF00FF", "score": 40,  "len": 7,  "place": 2 }
  ],
  "sessionScore": [
    { "id": "a1b…", "name": "Алиса", "color": "#00FFFF", "total": 120 },
    { "id": "b3f…", "name": "Боб",   "color": "#FF00FF", "total": 40 }
  ]
}
```
- `results`: отсортированы по `score` desc, `place` — с 1 (при равенстве очков
  порядок детерминирован сортировкой, места всё равно последовательные).
- `sessionScore`: сумма очков за все раунды сессии, desc. После этого все
  возвращаются в лобби (приходит `lobby_update`), новый раунд — по `start_game`.

### `error` — ошибка обработки сообщения (лично отправителю)
```json
{ "type": "error", "code": "bad_request", "message": "код комнаты: 5 символов из алфавита" }
```
Коды: `bad_request` (битый JSON, неизвестный `type`, невалидные поля,
сообщение больше `MAX_MESSAGE_BYTES`), `no_room`, `room_full`, `not_in_room`,
`not_host`, `already_running`, `no_session` (reconnect: сессия не найдена,
истекла или игрок уже подключён), `internal` (непредвиденная ошибка сервера).
Ошибка не разрывает соединение.

### `pong` — ответ на `ping`
```json
{ "type": "pong" }
```
